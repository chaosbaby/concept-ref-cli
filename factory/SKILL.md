# Concept CLI Factory (Interactive & Sensing Edition)

本技能通过渐进式交互，引导 Agent 与用户协作构建高性能 CLI 工具。

## 核心流程 (SOP)

### Phase 0: 诊断与感知 (Sensing & Diagnosis)
在编写任何代码前，必须先进行轻量级扫描：
1. **目录嗅探**: 扫描项目结构，寻找 `data/`, `scripts/`, `README.md` 及其他功能目录（如 `rank/`, `strains/`）。
2. **数据取样**: 读取 JSON/CSV 的前几行，分析字段结构。
3. **重复性评估**: 抽样检测是否存在同名异实（如多个《无题》）或同实异名/异排版（如换行符差异）的情况。
4. **输出报告**: 给出一个诊断报告，包含：
   - 数据规模预估。
   - 建议的 Schema 与 **去重策略** (如：标题+作者强去重)。
   - **发现的额外功能**: (例如：“检测到 rank 目录，建议集成热度搜索功能”)。
   - **潜在问题**: (例如：“检测到繁简混杂，建议强制简体化导入”)。
5. **决策点**: 询问用户是否同意诊断结果，并选择首选功能。

### Phase 1: 基础构建 (Base Implementation)
根据 Phase 0 的结果，实现“金标准”工具集：
- `init`: 高性能 SQLite 导入。
    - **智能去重**: 集成内容指纹与多级 Key 校验。
    - **来源优先级**: 优先处理标注明确的高质量源。
    - **性能加速**: 默认开启 WAL 模式与内存同步。
- `search`: FTS5 全文搜索 + 精确匹配。
- `stream`: 支持管道输入（stdin）和输出（NDJSON/Plain）。
- `completion`: 自动安装 Shell 补全。

### Phase 2: 渐进式增强 (Interactive Expansion)
根据 Phase 0 嗅探到的线索，逐一向用户推介增强模块：
- **模块 A (百科/作者)**: 如果有作者详情数据。
- **模块 B (分析/统计)**: 如果有 rank 或分类数据。
- **模块 C (交互/随机)**: 提供随机推荐或垂直排版。
- **每次增强后**: 演示功能，并给出接下来的 3 个改进选项。

### Phase 3: 交付与体检 (Delivery & Doctor)
- `doctor`: 检查数据库状态、索引健康度。
- `readme`: 自动生成使用说明。

## 交互准则
1. **反馈回路**: 每一个工具调用（如 `write_file`, `init`）后，必须向用户简报结果。
2. **选择驱动**: 禁止一次性完成所有功能。每步之后给出 [A], [B], [C] 选项供用户决策。
3. **轻量引导**: 优先使用文件名和 README 进行逻辑推理，减少对用户的主动提问。

## 技术协议 (The Standards)
- **DB**: `~/.<tool_id>.db`。
- **Format**: 必须支持 `--json` (单行) 和 `--plain` (彩色)。
- **Stream**: `sys.stdin` 必须能处理 `search` 查询流。
